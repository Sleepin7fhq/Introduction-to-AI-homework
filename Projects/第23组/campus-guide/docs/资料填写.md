# 三栋建筑资料填写说明

A 整理资料，B 将核实过的文字填入 [正在使用的三张资料卡](../data/buildings.json)。[保留的占位模板](../data/buildings.example.json) 可随时对照。保存为 UTF-8 JSON，刷新本地页面查看。

## 每栋楼交给 B 的内容

| 内容 | 填写方法 |
| --- | --- |
| 名称与编号 | 使用有来源支持的名称。暂按实拍与校史辨认时，用校区和用途给出稳妥称谓，将待核的照片原标注填入 `photo_label`。本项目沿用 A、B、C 三个编号。 |
| 外观线索 | 写照片中能直接看到、能帮助区分候选的特征，例如门窗形状或塔楼位置。每项可独立核对。 |
| 讲解事实 | 一条写一个意思，写成可以直接读给参观者的完整句子。将最适合开场的句子排在前面。缺少证据的年份、人物、用途先留空。 |
| 事实出处 | 网页记下真实标题和原始链接。实地观察记下照片或记录名、日期与观察内容，网页地址可留空。一条事实可引用多个出处。 |
| 照片 | 每栋楼可放一至两张清晰参考图，在不同角度留出待测照片。每张参考图的归属应能从现场记录确认。 |

## 一张卡的字段

以下是一张可复制的填写模板。三张卡放在同一个 JSON 数组中，分别使用不同的建筑编号。

```json
{
  "id": "A",
  "name": "【占位】填写建筑正式名称",
  "placeholder": true,
  "visual_cues": ["【占位】填写一个可观察的外观特征"],
  "reference_images": [],
  "sources": [
    {"id": "s1", "title": "【待填】原始页面标题或现场记录名称及日期", "url": ""}
  ],
  "facts": [
    {
      "id": "f1",
      "text": "【占位】填写一句由 s1 支持的讲解原句。",
      "keywords": [],
      "source_ids": ["s1"]
    }
  ]
}
```

- 把照片放入 [reference_images](../data/reference_images/)，再将实际文件名填入 `reference_images`。文件名大小写须一致。该字段留 `[]` 时，界面会提示参考图待补充。
- `source_ids` 与同卡 `sources` 中的 `id` 对应。只有已填写的 HTTP 或 HTTPS 地址会显示为链接。现场记录只显示标题。暂缺来源时两个列表均可写 `[]`，界面会说明尚无来源。
- `keywords` 用于离线追问，可填游客可能使用的词，例如“入口”或“圆窗”。真实模型直接读取事实原句。
- 可选字段 `guide_fact_ids` 按常规讲解的顺序列出本卡事实编号。前两条分别写名称与年代或原用途、现场可见的一处特征，详细版最多用前六条。年份分歧和名称考证可放在其余事实里，供追问使用。未设置讲解顺序的卡仍可使用。
- 历史事实引用学校材料，外观引用实际照片。综合判断须交代实拍所见和文字依据。来源发布日期和核查日期分别保存在[核查记录](建筑资料核查_2026-11-20.json)中。
- 全部占位文字替换并核对后，将本卡的 `placeholder` 改为 `false`。内置示意图仅供占位 A 卡演示。
