## 每条记录包含什么

```json
{
  "id": "bang-ba-bang",
  "name": "邦吧邦吧邦吧",
  "category": "鬼畜",
  "era": "2026",
  "origin_note": "【事实】司凤音乐中的招牌空耳拟声……（含未核验说明）",
  "context": "原始语境",
  "usage": "现在常见用法",
  "variants": ["邦吧邦吧邦吧", "崩巴崩巴", "邦吧邦吧，哒啦哒啦"],
  "punchline": "一本正经的失恋情歌，突然变成野人喊麦。",
  "music_fit": "天然的三音节节奏动机，可直接当 scat hook 排进 16 分网格……",
  "style": "sifeng_rave",
  "bpm": 167,
  "timbre": "粗粝男声 scat + 失真 kick + bitcrush 人声",
  "prompt": "raspy male scat hook, nonsense syllables, distorted rave kick, 167 bpm",
  "sources": ["https://cnmeme.wiki/entry/...", "https://www.geng8.com/word/..."],
  "confidence": "high",
  "verified": true
}
```

`style` 直接映射到 7 个风格预设之一；`bpm` 决定生成速度；`timbre` 进梗卡的"编制"栏；
`prompt` 可作为将来接入 LLM/ACE-Step 时的英文提示词。

## 来源与真实性策略

研究阶段（子代理执行）的硬规则：

1. **不编造** UP 主、播放量、发布日期；
2. `sources` 只放真正打开过的页面；打不开的放搜索页并注明"仅读摘要"；
3. 区分**原始出处**与**二创衍生**，两者冲突时不合并；
4. 抓不到正文的新梗（如 2026 年的"中国人会飞""奶蛙"等）一律 `low + verified:false`，并在 `origin_note` 写【待核实】。

已知未采用的信息（明确标注）：

- 「司凤 = 死冯避审谐音」只有 NGA 搜索摘要，未证实，不采用；
- 「名称来自《琉璃》角色」只有梗百科一处，标【待核实】；
- 搜索里出现的两个冲突 BV 号（BV1mgHd6bEDj / BV1faak6AEzm）未核验，不写入。

## 界面上的呈现

梗卡右下角会显示：

- **置信度徽章**：已核实（青）/ 部分核实（灰）/ 待核实（黄）
- **来源域名**（取 `sources[0]` 的 host）

这两项让"这个梗的说法靠不靠谱"在界面上一眼可见，而不是黑箱。

## 怎么扩充

1. 在 `研究/热梗候选.json` 里追加一条（字段齐全，`sources` 必填）；
2. `python scripts/gen_meme_kb.py` 重新生成 `memeKB.ts`；
3. `npm test`（`tests/core.test.ts` 有梗库命中用例）；
4. 若新梗需要新的编制，在 `styles.ts` 里加风格。

> 手工条目（`CURATED_MEMES`）永远优先于知识库条目：它们带有完整的鼓型/贝斯/切片映射，
> 生成质量更可控。知识库的作用是"扩大覆盖面"，不是"替代手工调校"。
