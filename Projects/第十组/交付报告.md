## 二、音频验证数据

验证方式：`python scripts/verify_audio.py <wav>`
不做"看文件大小"式判断，而是解析 RIFF 头 + 逐样本统计。

| 文件 | 时长 | 格式 | 大小 | 峰值 | RMS | 非静音占比 |
|---|---|---|---|---|---|---|
| acestep-techno-128bpm.wav | **11.868 s** | 48 kHz · 立体声 · float32 | 4,557,592 B | −1.00 dBFS | −15.82 dBFS | **93.3%** |
| acestep-early8-rave-138bpm.wav | **10.623 s** | 48 kHz · 立体声 · float32 | 4,079,256 B | −1.00 dBFS | −16.85 dBFS | **98.0%** |

逐秒 RMS 曲线（证明有真实动态，不是恒定音或静音）：

- techno：−15.9 / −15.8 / −15.8 / −14.5 / −16.1 / −16.3 / −15.1 / −15.7 / −15.6 / −16.7 / −15.3 dB，标准差 15.4 dB
- rave：−16.3 / −15.7 / −18.0 / −16.0 / −16.9 / −16.7 / −15.9 / −18.2 / −16.2 / −17.7 dB，标准差 17.9 dB

### 一处必须说明的实现细节

turbo 模型对 `duration` 条件并不精确：请求 14 秒，实际只有 11–12 秒有内容，尾部是一段约 **−60 dB 的残留噪声**。
服务端因此加入**尾部静音裁剪**：按 −46 dBFS 阈值定位最后一个有效帧，保留 0.25 秒尾巴后截断。
接口返回的 `duration` 是**裁剪后的有效时长**（`duration_requested` 保留原始请求值）。
不做这一步，演示时听起来会像"音乐突然断了"。

## 三、后端接口测试结果

服务地址：`http://127.0.0.1:8000`　启动脚本：`D:\AI\aihw\.tmp\ace\serve.py`

| 检查项 | 结果 |
|---|---|

| `POST /generate` 第二次 | HTTP 200，墙钟 **7.6 s**，推理 7.48 s，显存峰值 **4.62 GB**，最终时长 10.62 s |

### 接口契约

| 接口 | 入参 | 返回 |
|---|---|---|
| `GET /health` | — | `status` / `model` / `backend` / `offload` / `quantization` / `lm` / `load_seconds` / `uptime_seconds` / `error` |
| `POST /generate` | `{prompt, duration, bpm, steps, seed}` | `{audio_url, duration, duration_requested, bpm, generate_seconds, peak_vram_gb, model}` |
| `GET /audio/<name>` | — | `audio/wav` 字节流 |

> CORS 是实测踩到的坑：没有 `Access-Control-Allow-Origin`，前端（5173）对服务（8000）的 `/health` 与 `/generate` 会被浏览器预检直接拦住，表现为"服务明明活着，前端却显示不可用"。

## 八、开发过程中修复的真实缺陷

1. **时间轴错位 18px**：段落条占了高度，左侧轨名列没有对应占位 → 重排时间轴，移除重复轨名列。
2. **构建脚本编码**：`build.ps1` 无 BOM，PowerShell 5.1 按 ANSI 解析脚本内中文导致双重编码、页面显示乱码 → 加 BOM + `--charset=utf8`，并加启动期错误横幅（白屏可诊断）。
3. **播放读数**：播放时拍号显示成占位圆点 → 改为 1–4 真实滚动。
4. **`audio_url` 相对路径**：音频请求打到前端 5173 上 404 → 补服务源。
5. **`/health` 状态误判**：`loading` 被当成可用 → 检查 `status === 'ready'`。
6. **CORS 缺失**：跨源请求被浏览器预检拦截 → 服务端加 `CORSMiddleware`。
7. **尾部静音**：模型输出后段为 −60 dB 残留噪声，第一版阈值（−62 dB）失效 → 改为 −46 dBFS 并裁剪。
8. **解释器版本**：系统 Python 3.14 无法加载 cp312 扩展 → 固定使用 3.12 venv。

## 十、已知限制（不粉饰）

- ACE-Step 生成的是**音频**，没有音符结构，不能在时间轴上编辑（界面明确标注）
- turbo 对 duration 不精确，服务端做尾部静音裁剪；极安静的结尾可能被多裁一点
- 本地符号引擎是算法作曲 + 合成器音色，不是神经网络
- 旋律采用「动机 + 变奏」，撑不起完整发展部
- 不支持多轨音频录制、自动化曲线、撤销栈
- 一次只服务一个生成请求（服务端串行锁）

## 十三、后续升级（2.1 / 2.2）

交付后针对「本地音色像提示音」继续做了两轮升级，**不影响 ACE-Step 的既有能力**：

### 2.1 音色引擎重写

- 重写 `src/music/voices.ts`：三层 Kick、三层军鼓、三连击拍手、sub+mid 双层贝斯、
  3–5 层 detune 主音、共振峰人声切片、每轨独立混响/延迟送出、总线 EQ3 + 驱动；
- 新增 7 个风格预设（`src/music/styles.ts`）：司凤 Rave / 鬼畜切片 / 热梗 Techno /
  Hardstyle / Hyperpop / 经典 EDM / 混沌 Rave；
- 修复「锁定风格不生效」的 bug：以前 `composeSongEx` 会按文本重新推断流派；
- 热梗库 16 → 58 条（42 条带来源与置信度，未核实的标「待核实」）。

### 2.2 采样库与采样器

- 自建 **52 个 one-shot 采样**（48kHz/16bit，CC0 自制，9.1MB，16 个分类）；
- 新增 `src/audio/sampler.ts`：`AudioBufferSourceNode` 触发，支持变调、力度、声像、
  复音、切片；7 套 kit 按风格切换鼓组/贝斯/主音/人声切片；
- 采样不可用（如 `file://` 直开）时自动回退 2.1 合成音色；
- 客观效果：kick 低频占比 34%→46%，air 6.8%→12.2%，离线渲染耗时 14–17s → 1.2–3.0s。

### 关于采样来源的说明

尝试过 MusicRadar（CDN TLS 被拦）、Freesound（仅 MP3 预览）、archive.org（CC0 条目与
描述冲突）、Wikimedia Commons（0 命中），均未能取得合规可用素材，故采样为本项目
DSP 自制（`scripts/build_samples.py`），版权干净、可商用。
