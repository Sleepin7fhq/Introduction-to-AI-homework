# 🔒 隐私说明与合规设计

> 宿舍噪音智能识别与分类提醒系统 · 隐私合规说明书
> 版本：四类 RMS 门控版 ｜ 适用范围：本项目全部代码（`kernel/` C++ 内核、`ui/` Gradio 外壳、`scripts/` 转换脚本）

---

## 0. 一句话结论

**本系统不产生任何录音文件、不保存任何原始音频、不做语音识别、不转写任何文字。**
麦克风音频只在内存中短暂停留（默认最长 30 秒环形缓冲），提取完特征、推理完成后立即被覆写擦除。

---

## 当前分类与电平数据

当前输出类别顺序为 `loud_talk`（大声喧哗）、`normal_volume`（正常音量）、`game_audio`（游戏外放）、`normal_talk`（正常交谈），默认累计时长阈值为 [15, 9999, 45, 9999] 秒。内核逐段计算 RMS，低于或等于可配置 `normal_volume_dbfs`（默认 -45 dBFS）优先归正常音量，高于门限才做语义分类；低置信度或主要为其他标签时保留未分类，不硬归正常交谈。

IPC 中 `rms_dbfs` 是结构化的相对数字电平，不含波形或语音文字；它不是经过校准的 dB SPL 声压级。增加 RMS 门控不改变原始 PCM 与特征的内存擦除约束。

## 1. 隐私硬性约束与逐条落地

| # | 约束（题目要求） | 本项目实现 | 代码位置 |
|---|---|---|---|
| 1 | **不存储原始音频** | 内核只使用 `std::vector<float>` / `std::deque<float>` 等纯内存缓冲；全项目**没有任何** `ofstream`/`fopen`/`WriteFile` 写音频文件的调用。可现场举证：`Select-String -Path kernel\src\*.cpp -Pattern "fopen|_wfopen_s|fwrite|ofstream|CreateFile"` 只有 4 处命中，**全部是 `"rb"` 只读**（main.cpp:357/360 读黄金向量、wav_reader.cpp:36/39 读用户指定的 WAV），无任何写路径 | `kernel/src/*.cpp` |
| 2 | **不保存人声** | 模型只输出 527 类 AudioSet 标签的**概率分布**；不输出声纹、不输出说话人、不输出任何可还原人声的中间表示 | `kernel/src/classifier.cpp` → `Aggregate()` |
| 3 | **不做语音识别转文字** | 项目不含任何 ASR / STT 模型或库；没有 Whisper、没有 CTC、没有解码出文本的通路 | 全项目 |
| 4 | **特征提取 + 推理完成后原始音频立刻释放丢弃** | 推理返回后立刻调用 `SecureZero()` 对分段 PCM 与特征张量做逐字节覆写（`volatile` 写，编译器不可优化掉）；缓冲区随后 `clear()` + `shrink_to_fit()` 归还内存 | `kernel/src/pipeline.cpp` → `ConsumeSegment()` |
| 5 | **不留录音文件** | 离线推理读取用户**主动指定**的本地文件，但读完即用、只保留特征；内核不复制、不转存、不缓存 | `kernel/src/wav_reader.cpp` + `pipeline.cpp` → `ProcessOffline()` |
| 6 | **UI 只接收结构化结果** | IPC 协议里只有 `type/class_key/class_zh/confidence/top_label_name/duration_sec/threshold_sec/...`；协议中**不存在**任何承载音频样本的字段 | `kernel/include/dn/ipc_server.h`、`ui/kernel_client.py` |

## 2. 数据流全图（数据在哪里、存在多久）

```
       麦克风 / 本地文件
              │
              ▼
    ┌──────────────────────┐
    │  C++ 内核 (dorm_noise_kernel.exe)         │
    │                                      │
    │  miniaudio 采集 ──► std::deque<float> ring   │  ← 环形缓冲，硬上限 30 秒
    │                       │                  │     超限丢弃最旧，绝不无限增长
    │                       ▼                  │
    │              分段 (默认 5 秒)              │
    │                       │                  │
    │                       ▼                  │
    │         ┌────────────────────┐         │
    │         │ 特征提取 kaldi-fbank │         │  ← 只留 1024×128 的梅尔频谱
    │         │  (float32, 512 KB)  │         │
    │         └─────────┬──────────┘         │
    │                   ▼                    │
    │         ┌────────────────────┐         │
    │         │ ONNX Runtime 推理   │         │  ← AST 分类，输出 527 维 logits
    │         └─────────┬──────────┘         │
    │                   ▼                    │
    │        SecureZero(PCM) + SecureZero(特征) │  ← ★ 原始音频在此刻被擦除
    │                   │                    │
    │                   ▼                    │
    │      RMS 门控/语义归类 + 累计时长 + 阈值判断    │
    └───────────────────┬────────────────────┘
                        │  本地回环 socket (127.0.0.1)
                        │  仅 JSON 结构化结果
                        ▼
              ┌──────────────────┐
              │  Gradio UI 外壳    │
              │  （另一进程）       │
              └──────────────────┘
```

**关键点：UI 是独立进程**。即便 UI 被恶意替换，它能看到的也只有分类结果，无法拿到音频；
即便内核被单独运行，它也只会向回环端口发结果，不写文件。

## 3. 内存中的音频是怎么被擦掉的

`kernel/src/pipeline.cpp`：

```cpp
// volatile 写：编译器不会把这几行优化掉，确保真的被覆写
void SecureZero(void* data, size_t bytes) {
  volatile unsigned char* p = static_cast<volatile unsigned char*>(data);
  for (size_t i = 0; i < bytes; ++i) p[i] = 0;
  // 再写一遍 0xFF，防止某些编译器/优化器把常量折叠成 memset(0)
  for (size_t i = 0; i < bytes; ++i) p[i] = 0xFF;
}
```

推理流程（节选）：

```cpp
// ConsumeSegment():  一段音频的生命周期
std::vector<float> segment = ...;          // ① 该段 PCM
std::vector<float> features;
feature_extractor_.Extract(segment, &features);   // ② 提特征（只读 segment）
classifier_->Infer(features, &logits, &ms);        // ③ 推理
SecureZero(segment.data(), segment.size() * sizeof(float));   // ④ ★ 擦除原始音频
SecureZero(features.data(), features.size() * sizeof(float)); // ⑤ 擦除特征
segment.clear();  segment.shrink_to_fit();
features.clear(); features.shrink_to_fit();
```

> ⚠️ 诚实说明：`SecureZero` 能阻止**本进程**内的残留被后续读取，也防止 core dump
> 把音频写盘。但操作系统层面的内存交换（page file）不在本项目控制范围内。
> 若部署环境对隐私有更高要求，建议关闭系统页面文件或使用加密内存 —— 本项目
> 已把这列为「可选加固项」写在下方。

## 4. 不做什么（Negative List）

本项目**明确不包含**以下能力，代码里没有对应实现：

- ❌ 录音 / 录音文件保存 / 音频导出 / 音频上传
- ❌ 语音识别（ASR）、语音转文字、字幕生成
- ❌ 声纹识别、说话人识别、身份关联
- ❌ 摄像头 / 图像采集
- ❌ 云端推理（本模型 100% 本地运行，模型文件 330 MB 完全离线）
- ❌ 任何形式的遥测 / 上报 / 数据外发（内核只监听 127.0.0.1）

## 5. 网络行为

| 组件 | 是否联网 | 说明 |
|---|---|---|
| C++ 内核 | ❌ 不联网 | 只绑定 `127.0.0.1:8765` 回环端口，模型从本地磁盘加载 |
| Gradio UI | ⚠️ 默认本地 | `server_name="127.0.0.1"`，`share=False`；**不添加 `--share` 即可保证完全不出本机** |
| 转换脚本 | ⚠️ 仅一次 | `scripts/export_ast_onnx.py` 从 HuggingFace 下载模型权重，属于**开发期**行为，产出的 ONNX 之后完全离线 |
| 下载脚本 | ⚠️ 仅一次 | `scripts/fetch_real_audio.py` 从 Wikimedia Commons 下载演示音频，仅用于答辩素材 |

> 演示现场建议：**先在有网环境准备好所有素材**，现场断网演示也不影响功能。

## 6. 数据最小化对照表

| 数据项 | 采集？ | 留存？ | 留存多久 |
|---|---|---|---|
| 原始 PCM 音频 | ✅ 实时采集（这是功能本身必需） | ❌ 不留存 | 内存中 ≤30 秒，推理后立即覆写 |

| 告警事件 | ✅ | ✅ | UI 进程内最近 20 条 |
| 人声内容/文字 | ❌ | ❌ | 从不产生 |
| 声纹/说话人 | ❌ | ❌ | 从不产生 |

## 7. 用户可见的隐私控制

UI「参数配置」页与内核命令行都提供：

- `reset` 命令：一键清零所有累计时长与告警（`ui/app.py` → 「🧹 清零统计」）
- `stop_capture`：立即停止麦克风采集
- 内核进程退出：所有内存态统计随进程消失
- 离线推理：内核**只读取用户明确指定的路径**，不扫描目录、不批量处理

## 8. 可选加固建议（超出题目要求，供评审参考）

1. 关闭操作系统页面交换，或使用 `mlock` 锁定音频缓冲页，避免 swap 文件落盘。
2. 内核以低权限用户运行；IPC 端口加访问控制（当前已限定回环）。
3. 审计 `SecureZero` 调用点（`pipeline.cpp`），确保未来新增代码路径也走同一出口。
4. 若需更强证明，可用 `strace`/ETW 记录文件写系统调用，展示「运行 10 分钟，磁盘上 0 字节音频写入」。

## 9. 一句话向评审承诺

> 本系统在你说话时**听了又忘**：它只记住「刚才那 5 秒属于哪一类噪音」，
> 不记住你说了什么、不保存你说过这句话的证据。
> 磁盘上不会出现任何录音文件，内存里的原始音频在推理完成的那一瞬间就被覆写。
