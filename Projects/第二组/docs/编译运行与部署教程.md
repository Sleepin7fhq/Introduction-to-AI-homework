### 4.4 ⚠️ MinGW 必读：`_stdcall=` 编译标志

ONNX Runtime 的 `onnxruntime_c_api.h` 在 `#ifdef _WIN32` 分支里把 `ORT_API_CALL`
定义成 MSVC 关键字 `_stdcall`。GCC 不认识它，会把整个 `OrtApi` 函数指针表解析坏，
报出**几十条**类似

```
error: 'const OrtApi' has no member named 'CreateValue'
error: 'const OrtApi' has no member named 'GetVersionString'
```

的**假报错**（看起来像"头文件版本和 DLL 不匹配"，其实根因只有这一条）。

`kernel/CMakeLists.txt` 已经处理：

```cmake
if(MINGW OR CMAKE_CXX_COMPILER_ID STREQUAL "GNU")
  target_compile_options(dorm_noise_kernel PRIVATE -U_stdcall -D_stdcall=)
endif()
```

> 为什么是 `-U` 再 `-D` 而不是直接 `-D_stdcall=`：
> MinGW 的 GCC **自己**就预定义了 `_stdcall = __attribute__((__stdcall__))`，
> 直接 `-D` 会触发 `'_stdcall' redefined` 警告。
> GCC 按命令行顺序处理 `-D` / `-U`，**先 `-U` 撤销预定义、再 `-D` 覆盖为空**才能干净生效。
> （本机实测：A 直接 -D 能编过但有警告；B 先 -U 后 -D 干净通过；C 不覆盖直接报
> `onnxruntime_c_api.h:334: error: expected ')' before '*' token`。）

> 第二个坑：`onnxruntime_cxx_api.h` 里 `Global<T>::api_` 是**动态静态初始化**，
> 跨翻译单元顺序不确定。若在全局对象构造期就创建 `Ort::Env`，会解引用空指针崩溃。
> 本项目在 `kernel/src/classifier.cpp` 里 `#define ORT_API_MANUAL_INIT` 并自写
> `EnsureOrtApi()`（`std::call_once` 调 `Ort::InitApi(...)`）解决。

## 5. 运行

### 5.1 内核命令行

```powershell
cd build\bin

# 帮助
.\dorm_noise_kernel.exe --help

# 启动内核（开麦 + IPC 服务，端口 8765）
.\dorm_noise_kernel.exe --model ..\..\models\ast_audioset.onnx --port 8765

# 不开麦（只跑 IPC 服务，供 UI 演示配置/离线推理）
.\dorm_noise_kernel.exe --model ..\..\models\ast_audioset.onnx --no-capture

# 离线推理（答辩最常用）
.\dorm_noise_kernel.exe --offline ..\..\models\ast_audioset.onnx ..\..\assets\audio_demo\real_speech_0.wav

# 特征数值自检（C++ 特征 vs Python 黄金向量）
.\dorm_noise_kernel.exe --selftest ..\..\models\golden\fbank.bin ..\..\models\golden\golden.wav

# 换 int8 模型（91 MB，推理快 1.9×）
.\dorm_noise_kernel.exe --model ..\..\models\ast_audioset_int8.onnx

# 手动指定推理线程（默认 0 = 自动取 CPU 核数一半，上限 8）
.\dorm_noise_kernel.exe --model ..\..\models\ast_audioset.onnx --threads 8
```

主要参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | `models/ast_audioset.onnx` | ONNX 模型路径 |
| `--port` | `8765` | IPC 端口（仅监听 127.0.0.1） |
| `--threads` | `0`（自动 = CPU 核数/2，上限 8） | 推理线程数；0 表示自动 |
| `--segment-sec` | `5.0` | 分段长度（秒） |
| `--no-capture` | 关 | 不开麦克风 |
| `--offline [onnx] wav` | — | 离线推理（可省略 onnx 参数） |
| `--selftest fbank.bin wav` | — | 特征数值比对 |

### 5.2 启动 UI

```powershell
python ui\app.py                 # 默认连内核 127.0.0.1:8765
python ui\app.py --port 9000     # 换内核 IPC 端口
python ui\app.py --ui-port 7861  # 换 Gradio 界面端口（7860 被占用时用）
```

浏览器打开 `http://127.0.0.1:7860`（若加了 `--ui-port` 则换成对应端口）。

> UI 默认 `server_name="127.0.0.1"`、`share=False`，**完全不出本机**。
> 不要加 `--share`，否则 Gradio 会生成公网临时链接。

### 5.3 一键联调（Windows）

```powershell
# 终端 1：起内核
.\build\bin\dorm_noise_kernel.exe --model .\models\ast_audioset.onnx
# 终端 2：起 UI

```

## 6. IPC 协议（内核 ↔ UI）

**传输**：TCP `127.0.0.1:8765`，每行一个 UTF-8 JSON 对象，`\n` 结尾。

### 当前四类与电平门控

类别顺序固定为 `loud_talk`（大声喧哗）、`normal_volume`（正常音量）、`game_audio`（游戏外放）、`normal_talk`（正常交谈），默认累计时长阈值为 **[15, 9999, 45, 9999] 秒**。9999 是较大阈值而非无限时长。

每段先计算 `rms_dbfs`，**RMS ≤ `normal_volume_dbfs`（默认 -45 dBFS）优先判为正常音量**。高于门限才做三类语义判定；低置信度或主要为其他 AudioSet 标签的片段保留未分类，不硬归正常交谈、不计入四类累计。乐器声不再是输出类别。`normal_volume_dbfs` 可通过 `set_config` 调整。

电平是相对数字满刻度的 dBFS，不是 dB SPL 声压级；换设备、麦克风增益或距离后应重新校验门限。下面 JSON 是协议字段示例，不是新版实测准确率报告。

### UI → 内核

```json
{"cmd":"status"}
{"cmd":"set_config","segment_sec":5.0,"thresholds":[15,9999,45,9999],"min_confidence":0.05,"normal_volume_dbfs":-45.0,"auto_alert":true}
{"cmd":"start_capture"}
{"cmd":"stop_capture"}
{"cmd":"reset"}
{"cmd":"offline_file","path":"C:/path/to/audio.wav"}
{"cmd":"quit"}
```

> **rid 请求-响应配对**：UI 每条命令都会带一个唯一 `rid`（如 `{"cmd":"status","rid":"02275bf9"}`），
> 内核在响应里原样回填 `"rid":"..."`；**周期性 state 广播不带 rid**。
> 这样 UI 就能精确区分「命令响应」和「状态广播」，不会被 500 ms 一次的广播挤掉
> （`ui/kernel_client.py` 的 `_pending` 字典按 rid 配对）。
> 直接用命令行/脚本裸连内核时 rid 可省略。

### 内核 → UI

```json
{"type":"ok","cmd":"set_config"}
{"type":"error","message":"未知命令: bogus"}
{"type":"state","kernel_alive":true,"capture_running":true,"device_name":"...","model_path":"...",

 "last":{"class_index":3,"class_key":"normal_talk","class_zh":"正常交谈","confidence":0.85,
         "top_label_id":0,"top_label_name":"Speech","top_label_prob":0.79,"rms_dbfs":-25.0,"segment_sec":5.0},
```

## 7.5 便携单文件 exe（双击即用）

不想在答辩现场装依赖？用便携版：**内核 + ONNX Runtime 运行时 + 模型** 全部内嵌进一个 exe。

```powershell
# 构建（默认 int8 模型 → 102.5 MB；加 --fp32 则是 330 MB）
python scripts\build_portable.py --out-name "宿舍噪音识别.exe"
#    产物：build\portable\宿舍噪音识别.exe
```

### 工作原理

1. `ld -r -b binary` 把 `dorm_noise_kernel.exe`、`onnxruntime.dll`、
   `onnxruntime_providers_shared.dll`、`ast_audioset_int8.onnx` 变成 4 个 `.o`，
   以 `_binary_<name>_start/_end` 符号内嵌进启动器 `kernel/src/portable_main.cpp`。
2. 启动时按「先写 `.tmp` 再 `MoveFileEx` 改名」的**原子写**方式释放到运行目录；
   已存在且大小一致就复用，不重复写。
3. 释放目录按顺序尝试（每个都写探针文件验证真的可写）：
   `%LOCALAPPDATA%\DormNoise\runtime` → `exe 所在目录\DormNoiseRuntime` → `%TEMP%\DormNoiseRuntime`。
4. 用 `CreateProcessW` 启动真正的内核（`cwd` 设为释放目录），透传命令行与退出码；
   命令行里没有 `--model` 时自动补上释放出来的 int8 模型路径。

### 命令

```powershell
# 双击直接运行（等价于 --port 8765，开麦 + IPC）
.\宿舍噪音识别.exe

# 离线推理
.\宿舍噪音识别.exe --offline .\assets\audio_demo\real_speech_0.wav

# 只解包不运行（想手动看释放了什么）
.\宿舍噪音识别.exe --extract-only D:\somewhere

# 看帮助
.\宿舍噪音识别.exe --help
```

### 注意事项

- **原目录不会多出任何文件** —— 释放出来的资源全在运行目录里（可现场用
  `Get-ChildItem` 验证：解压前后文件数不变）。
- 释放目录里的 `dorm_noise_kernel.exe` 就是本体，删掉它下次运行会自动重新释放。
- 版本信息里的中文需要 `.rc` 首行写 `#pragma code_page(65001)`，
  否则 windres 会按本地 ACP(GBK) 解读导致乱码（`scripts/build_portable.py` 已处理）。
- 首次运行会花 1～2 秒释放 91 MB 模型，属正常。

## 9. 常见问题（FAQ）

| 现象 | 原因 | 解决 |
|---|---|---|
| `OrtApi has no member named CreateValue` 等几十条报错 | MinGW 未定义 `_stdcall` | 用本仓库的 CMakeLists（已含 `-U_stdcall -D_stdcall=`）；或手动加同样两个标志 |
| `CMake Error: Target DependInfo.cmake file not found` | `MinGW Makefiles` 生成器与 CMake 4.x 不兼容 | 换 `-G Ninja` |
| exe 启动即 `0xC0000005` 访问冲突 | 全局对象构造期 ORT API 尚未初始化 | 用本仓库的 `classifier.cpp`（含 `ORT_API_MANUAL_INIT` + `EnsureOrtApi()`） |
| `cannot open output file ... Permission denied` | 上一次崩溃残留的 exe 进程还在跑 | `Stop-Process -Name dorm_noise_kernel -Force` |
| 中文路径打不开文件 | 命令行是 GBK、JSON 是 UTF-8 | 用 `dn::ToWideFlexiblePath()`（已内置）；路径尽量不含特殊字符 |
| 麦克风没声音 | WASAPI 默认设备不对 | 检查系统默认录音设备；或用 `--offline` 走文件路径演示 |
| 推理很慢 | 模型 330 MB，CPU 单线程 | 用 `--threads 0`（自动取 CPU 核数一半，上限 8，实测本机 8 线程 fp32 ≈990 ms/段）；或换 int8 模型 |
| 端口被占用 | 上个内核没退出 | `netstat -ano | findstr 8765` → `taskkill /PID <pid> /F`；UI 端口用 `--ui-port 7861` |
| Gradio 页面打开报错 `Cannot find empty port in range: 7860-7860` | 7860 被别的程序占用 | `python ui\app.py --ui-port 7861` |
