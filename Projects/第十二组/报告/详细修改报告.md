## 1. 项目形态与封装路线（及依据）

- **形态**：一个纯 Node 的网关进程（`probe\hub-fix`，ws + node:http/fs/crypto，非 Electron），与 DSH 上游（`alt\`，Electron 应用内部子进程，N-API 模块跨 Node 版本 ABI 稳定）构成两个独立进程。依据：DSH 官方模型要求单进程独占 3080，网关作为"唯一安全边界"监听 0.0.0.0:3090，DSH 保持 127.0.0.1:3080。
- **封装路线**：Inno Setup 6（`PrivilegesRequired=lowest` 免管理员）→ 内置 Node v24.16.0（DSH 要求 ≥24.9）→ node_modules 三个 tar（alt 793.7MB / runtime 13.5MB / probe 0.2MB）随包分发、首次启动解压 → `lzma2/max`+`SolidCompression=yes` 压缩。依据：早期版本把 72,899 个小文件直接打进 exe，安装实测 293 秒；改 tar 后安装 18–29 秒、文件数降到 241。
- **排除清单**（`setup.iss` Excludes）：`installer,node_modules,*.log,logs,sessions.json,sessions,storages,.credentials.yaml,.anonymous-user-id,*.jar,__pycache__,*.pyc,*.tmp`——运行时数据、机器绝对路径、凭据、cookie jar 一律不随包分发（原始设计即"全新 dshhome 随包"）。

## 6. 已知限制与风险（诚实口径）

- **HTTP 明文**：3090 是 HTTP（LAN 内明文），未上 TLS；不建议跨公网使用。
- **默认密码**：交付账号 admin/alice/bob/carol 密码公开，靠**首登强制改密**兜底；改密后不再明文记录。
- **代码签名**：exe 未签名（无证书），SmartScreen 会拦；处理方式见简要说明。
- **权限模型单档**：网关按"owner/chat/viewer"三档；无每会话/每文件细粒度 ACL；工具层最小权限仅原型+报告讨论，未下沉 DSH 本体。
- **3080 边界**：DSH 仍监听 127.0.0.1:3080，靠回环绑定隔离；网关是唯一 0.0.0.0 面。
- **并发限制**：WS 连接上限 50，HTTP 代理无显式限流；节流仅覆盖登录。
- **用量估算**：token/成本为字符估算（每 4 字符≈1 token、输出 2×、占位价），非 DSH 实测；注入行在模型实际运行时才进会话历史。

## 7. 答辩可引用"问题—修复—验收"

1. **一键化**：装包慢（293s/7.3 万文件）→ tar 打包+内置 Node → 安装 18s/241 文件、免 Node 免 Inno。
2. **DSH 启动失败**：内置 Node v22 < DSH 要求 ≥24.9 → make-portable 升 v24.16.0+版本自检 → 启动稳定。
3. **权限模型**：成员只有"共享/不共享" → 多级 chat/viewer+路径围栏 → viewer 读得进、发消息被拒（rehearse CASE 9a/9b）。
4. **会话 id 过期**：全新安装演示 payload 失效 → rehearse 自愈建会话重建 payload → 新装 16/16。
5. **可靠性**：DSH 控制台窗口被 Ctrl+C 导致 502 → 双进程后台隐藏运行+stop-all → 三次误杀后不再复现。
