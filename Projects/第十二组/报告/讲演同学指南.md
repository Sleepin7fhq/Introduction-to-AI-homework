# 讲演同学指南（3 分钟现场汇报）

> 你的任务一句话：**用 3 分钟让老师看到"一个 AI，多个身份"是怎么真跑起来的。**
> 配套文件：《核心理念变更说明.md》（PPT 大纲）、《答辩问答预演.md》（10 问应对）。

---

## 一、提前一周准备清单

- [ ] **演示机装好**：装 setup.exe → 双击「DSH 共享网关」→ admin 首登改密。
- [ ] **配好 key**：admin 进 DSH 界面 → 模型设置 → 填 DeepSeek key → **亲手跑通一次真实回复**（确认 AI 能回话，这是身份注入演示的前提）。
- [ ] **预置好权限**：admin 在 `/admin` 工作区页，把 alice 设成「协作」、carol 设成「只读」——演示时不用现场点。
- [ ] **预登录两个窗口**：窗口 1 = admin 管理台（/admin），窗口 2 = alice 聊天界面；提前登录好别现场输密码。
- [ ] **彩排 3 遍，计时卡秒**（目标 2:45–3:00，见第七节记录）。
- [ ] **提前 1 天上传 Github**：代码仓库 + 安装包 + PPT（要求：提前 1 天）。

## 二、3 分钟讲演脚本（逐段卡秒）

### 0:00–0:30 开场定位（30 秒）
> 「我们的作品是《小组 AI 助教》——人工智能+教育。一句话：**一个 AI，多个身份**。」

翻到 PPT 第 1 页《一个 AI，四个问题》：
> 「大家共用一台 AI 时，会冒出四个问题：**它知道在为谁服务吗？谁能干什么？活儿轮到谁了？花了多少钱？** 我们把这四个问题全做进了系统。」

### 0:30–1:00 痛点（30 秒）
> 「现在一个小组要用 AI 助教，要么全组挤一个账号——谁发的消息不知道、乱用没人管；要么各买各的 key——烧钱。我们宿舍就遇到这个真实问题，所以做了这套系统。」

### 1:00–2:00 方案 + 现场演示（60 秒，全场灵魂）

**① 身份（10 秒）**——切 alice 聊天窗口，现场发一条消息：
> 「看，AI 知道在帮谁干活——回复里写着『正在为成员 alice 服务，角色：协作成员』。」

（若现场没网/没 key，跳过这步，直接讲下一句：「为省 key 我们测试不调真模型，配置了 key 后 AI 就会这样回复。」）

**② 权限（15 秒）**——切 carol（只读）发消息：
> 「carol 是只读成员——发消息被当场拒绝：『只读成员不能发送消息』。连路径逃逸（../）也全被拦。这不是界面提示，是网关层强制。」

**③ 协作（15 秒）**——切 admin 管理台「时间线」页：
> 「活儿怎么接力？——老师发任务、alice 接力第一段、转交接力棒给 bob、bob 接力第二段，全程留在审计时间线上，谁在何时做了什么，一清二楚。」

**④ 记账（15 秒）**——切「用量」页：
> 「花了多少钱？——每个人多少条消息、估算多少 token、多少成本、谁超额，账本在这里。」

收句：
> 「**四个问题，四个答案，全部是跑起来的代码。**」

### 2:00–2:30 技术可行性（30 秒）
> 「技术上：一个纯 Node 网关，不改上游一行代码；密码 scrypt 加盐、路径围栏、全量审计；权限矩阵 **32 项实测** + 演示脚本 **16 项全过**；打包成一个 120MB 的安装程序，双击就装好、装完自动打开浏览器，**不需要预装任何东西**。」

### 2:30–3:00 收尾（30 秒）
> 「不足我们诚实写在报告里：HTTP 明文（限局域网）、权限目前三档、用量是估算口径。下一步：把权限下沉到 Agent 工具层、接入精确用量。谢谢老师同学，欢迎提问。」

## 三、现场演示动线速查（卡壳就看这个）

```
① 切 alice 聊天窗口 → 发一条消息 → 指注入行
② 切 carol 窗口 → 发消息 → 指"只读成员不能发送消息"
③ 切 admin「时间线」页 → 从上往下指四行（老师/alice/转交/bob）
④ 切 admin「用量」页 → 指三个人的 token 与估成本
```

每一步对应脚本里的一小段话，**演示与口播永远同步**。

---

## 四、最可能被问的 3 个问题（先背这 3 个）

1. **「AI 在哪？这不就是登录系统吗？」**
   → 「模型是基础设施，我们解决的是**一个模型被 N 个人共用时的身份、权限、协作、治理**——这正是团队版 AI 工具的核心工程，四个落点都有代码。」
2. **「安全怎么保证？」**
   → 「密码 scrypt 不落明文；每次读文件都过路径围栏；3080 只在本机回环，同学只能走 3090 这一条受控边界；所有动作进审计。」
3. **「有什么不足？」**
   → 「HTTP 明文、权限三档、用量是估算——文档里全部诚实标注，并且每个都有明确的下一步路线。」

其余 7 问见《答辩问答预演.md》，紧张就背兜底三句（该文档末尾）。

## 五、翻车预案（演示出问题怎么接）

| 风险 | 预案 |
|---|---|
| 现场没网 / 没配 key，AI 不回话 | ① 跳过身份演示的"AI 回复"镜头，口播："为省 key 我们测试不调真模型，配置 key 后就是这样"；② 其余三张牌（权限/时间线/用量）**不需要模型**，照常演示 |
| DSH/网关没起来 | 提前 20 分钟到场：跑 start-all，看到「DSH 就绪」再开始；中途挂了 → stop-all + start-all 重启（约 2 分钟），这 2 分钟靠讲 PPT 拖 |
| 时间不够 | 优先砍"技术可行性"段（2:00–2:30 可压成一句）；**演示是灵魂，超时先砍口播不砍演示** |
| 浏览器里冒出旧测试会话 | 演示前清理无关会话（或提前重装一遍实例，全新干净） |
| 老师打断提问 | 用一句话回答后**拉回主线**：「这个问题报告里有详细说明，我先把演示走完，最后统一回答。」 |

## 六、同学互评加分点（E 展示效果 10 分）

- 演示时**指着屏幕说**，不要背对着屏幕念 PPT。
- 每个镜头一句话点题（身份/权限/协作/记账），同学打分是"看懂了多少"。
- 收尾留 3 秒停顿再致谢，显得稳。
