### D-01 [P2] 消息无大小上限（已修）
- **复现**：1MB 文本 prompt `accepted:true` 直达上游，无任何限制。
- **影响**：重复大消息可造成网关/上游内存与队列膨胀（演示误粘贴大段文本即触发）。
- **修复**：session/prompt 与 updateQueue edit 的纯文本总长上限 64KB，超出返回「消息过长（单次最多 64KB）」。
- **回归**：70KB 拒绝、短消息正常 ✅。

### D-02 [P2] 禁用账号后 WS 不主动关闭（已修）
- **复现**：admin 禁用 audit3 → REST 会话立即 302，但已建立的 WS 保持 OPEN（直到用户下次发消息才断）。
- **影响**：被禁用的成员仍能持续收流，权限撤销不彻底。
- **修复**：`/users/<name>/status` 路由在禁用时主动遍历 `context.memberStreams`，关闭该用户全部连接（1008）。
- **回归**：禁用后 800ms 内 WS close 事件触发 ✅。

### D-03 [P3] 重复 requestId 入队两次（已修）
- **复现**：同一 sessionId+requestId 连发两次，两次均 `accepted:true`（双击/刷新导致消息重复入队，演示时聊天框出现两条相同消息）。
- **修复**：网关按 `用户\0会话\0requestId` 缓存回执 30 秒，重复请求回放首次 envelope。
- **回归**：同 requestId 二次请求返回与首次一致的缓存回执 ✅。

### D-04 [P3] 去重缓存无视策略变化（已修）
- **复现**：CASE 6 入队成功 → 撤销共享 → 同一 payload 再发，命中去重缓存回放 `accepted:true`，绕过了撤销守卫（rehearse 8b 失败）。
- **修复**：命中缓存前重跑 `guardMemberRequest`，权限已变则作废缓存、走正常拒绝。
- **回归**：rehearse 16/16（8b 撤销后拒发恢复）✅。

## 五、B 类（高度可疑但未动态复现）

| 项 | 疑点 | 为何未测 |
|---|---|---|
| key 耗尽/无效时前端提示 | 队列 accepted 后 Agent 调用失败，错误帧为「request failed + upstream 错误码」，可能不够直白 | 无法在不破坏用户真实 key 的前提下复现（改 key 属修改用户凭据）；已备演示兜底方案 |
| 电脑休眠唤醒 | 长连接/会话在休眠后可能僵死 | 沙箱无法真实休眠；理论上有 WS 重连+会话 14 天 TTL 兜底 |
| 长会话挂机数小时 | 内存/句柄增长未量化 | 未做数小时级挂机；短时挂机（分钟级）无异常 |
| 大文件读取 | 仅验证 range 上限 5000 字节的防护存在 | 未构造 >5000 字节文件的逐字节验证（range 校验为代码级确认） |

## 七、无法验证项及缺什么条件

- 真实断网：需要物理断网；网络层异常已用"WS 断线重连 + 刷新登录态"替代验证。
- 休眠唤醒：无真实休眠环境。
- key 耗尽：不能破坏用户凭据（见 B 类）。
- 多机并发：无第二台机器（单机并发已测）。
